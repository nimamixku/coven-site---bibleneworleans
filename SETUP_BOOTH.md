# Setting up the Booth

The Booth is a small text oracle on the coven-site: you type a question, thought, or
feeling, and it answers in COVEN of New Orleans's own established voice — grounded in
the real writing on bibleneworleans.com (the covenant, testing-the-matrix, the
glossary, covenisms). It's owner-only for now, so only you (the "keeper") can trigger
it. Nothing about this touches the live bibleneworleans.com site.

Every answer is machine-generated by Claude and clearly labeled as such on the page —
no human reads or writes these in real time.

There are three one-time setup steps, all done in Vercel/Neon, similar to what you
already did for the Medical Terminology audio labels on the kaqchikel site.

## 1. Connect a Postgres database

If coven-site doesn't already have one:

1. Open the coven-site project on vercel.com
2. Go to the **Storage** tab
3. Add a **Postgres** database (Neon) if one isn't already connected — same flow as
   kaqchikel-site
4. This automatically adds `DATABASE_URL` (or `POSTGRES_URL`) to your project's
   environment variables

## 2. Run the schema

1. From the Storage tab, open the connected Neon database
2. In the left sidebar, click **SQL Editor**
3. Paste in the contents of `db/schema.sql` (in this same folder) and run it
4. You should see "Statement executed successfully" for the `create table` and the
   `create index`

This creates one table, `booth_log`, which privately stores every question asked,
the answer given, whether the safety boundary was triggered, the real dollar cost of
that API call, and a hashed (non-identifying) IP. Only you can read this log — there's
no public listing.

## 3. Add environment variables

In the coven-site Vercel project, go to **Settings → Environment Variables** and add:

- `ANTHROPIC_API_KEY` — your Anthropic API key (same kind of key used for the
  kaqchikel guessing game, if you have one already; otherwise create one at
  console.anthropic.com). This is what the booth uses to actually generate answers,
  and real API cost is billed against your Anthropic account each time you ask it
  something.
- `COVEN_KEEPER_PASSCODE` — pick any passcode. This is what you type into the "sign
  in as keeper" box on the booth to unlock it for yourself. Keep it private — anyone
  who knows it can trigger real API spend.

Optional, only if you want to change defaults later:

- `MAX_DAILY_BOOTH_ASKS` — a sanity cap on how many times the booth can be asked per
  day, across everyone who can ask it. Defaults to 100.
- `ANTHROPIC_BOOTH_MODEL` — defaults to `claude-haiku-4-5-20251001`. Only change this
  if you want a different model; if you do, also update `HAIKU_INPUT_PER_MTOK` /
  `HAIKU_OUTPUT_PER_MTOK` in `app/api/booth/route.js` to match that model's real
  pricing, since those numbers are what the price on the sign is computed from.

Redeploy (or just push — Vercel redeploys automatically) after adding these.

## Using it

Once deployed, scroll to the Booth section, click "sign in as keeper," enter your
passcode, and ask it something. The sign shows the real dollar cost of that specific
reading (computed from actual token usage), not a flat price.

## Opening it to the public later

Right now, only the signed-in keeper can ask the booth anything — asks from anyone
else return a 403. When you're ready to open it up:

1. In `app/api/booth/route.js`, find the comment above `MAX_TOTAL_PER_DAY` and the
   `if (!owner)` check in the `POST` handler
2. Relax or remove that check (you may want to add a per-IP cooldown at that point,
   since the daily total cap alone won't stop one person from asking dozens of times
   in a row)
3. Nothing else — not the database schema, not the frontend — needs to change

## A note on `pg` and package-lock.json

This update adds the `pg` package (for talking to Postgres) to `package.json`. The
sandbox I built this in couldn't reach the npm registry to regenerate
`package-lock.json`, so after you pull these files onto your Mac, run:

```
npm install
```

once in the coven-site folder before your next deploy. That will write a correct
`package-lock.json` locally, which you should commit along with everything else.
